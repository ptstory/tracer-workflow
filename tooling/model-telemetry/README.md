# Local agent telemetry

Harness-neutral local telemetry that joins saved agent-session metadata to pull requests, trusted Review Gate decisions, and later outcomes. It records observations about work that was already performed; it does not select, route, or launch models.

## What it records

For each observed session:

- session ID, repository, branch, and HEAD at first observation
- configured model separately from model and provider identities observed in saved-session messages
- reasoning effort observed in saved-session messages or metadata
- PR and closing-issue links when available
- outcome state: unsuccessful session, gate acceptance, actual PR merge, repair, escalation, reopened issues, and explicitly linked corrective PRs
- latest-step context/output token counters, cumulative recorded session cost, wall time, tool counts, and skill names

Observed identity is `unknown` when saved-session evidence is absent and `mixed` when more than one value occurs. Configured identity is never used to fill missing observed identity. Token counters are snapshots, not cumulative spend. Recorded cost is not subscription consumption or actual account spend.

For each trusted Review Gate comment, the collector stores the verdict, review round, reviewed-file count, blocking targets/findings, rebaseline state, reviewed head SHA, and timestamp. It uses the shared verdict parser and reviewer allowlist from `tooling/lib/verdict.ts`.

Only allowlisted metadata is persisted locally. Prompts, assistant messages, tool payloads, review prose, source code, diffs, and credentials are not copied into telemetry ledgers.

## Storage

Default state root:

```text
~/.local/state/tracer/model-telemetry/
  sessions/<session-id>.json
  attempts.jsonl
  reviews.jsonl
  allowance-observations.jsonl
```

Override the root with `TRACER_MODEL_TELEMETRY_ROOT`. Session markers are write-once; derived JSONL ledgers are regenerated by sync. The configured model, if captured, is a separate observation and never substitutes for a model observed in saved-session messages.

## Mark a session

```sh
bun tooling/model-telemetry/model-telemetry.ts mark
```

The marker is idempotent per session. Once it exists, later calls return after a file-existence check, before reading git state. On macOS with Bun 1.4.5 in this worktree, 30 fresh CLI processes measured marker-absent median 55.82 ms (p95 72.43 ms) and marker-present median 9.52 ms (p95 10.32 ms); these include process startup and git-context collection on absent markers, and are not an installed-hook benchmark. Hook installation and matcher choice are intentionally left to the separate harness integration. Matching every tool captures sessions that use any tool but runs the hook on every call. A narrow matcher such as `^bash$` reduces calls but misses sessions that never use that tool. Recommend matching every tool when complete capture matters; narrow matching trades completeness for fewer hook invocations.

A session with no tool call is not captured by a pre-tool hook. The current collector covers top-level sessions only.

## Sync and report

```sh
bun tooling/model-telemetry/model-telemetry.ts sync
bun run model:sync
bun tooling/model-telemetry/model-telemetry.ts report
bun run model:report
```

Sync reads session markers, requests saved metadata with `crush session show <id> --json`, resolves PRs and closing issues through GitHub, parses trusted Review Gate comments, and regenerates the derived ledgers. Set `TRACER_REVIEWER_LOGINS` to the trusted reviewer logins used by Tracer. Without a valid allowlist, attempts still sync and prior review telemetry is preserved; no new comments are trusted. No model is called during sync.

Use `report --no-sync` for local-only ledger reads and `report --json` for lifecycle JSON. Reports keep separate counts for gate acceptance, actual merge state, unsuccessful sessions, repairs, escalations, reopened issues, and explicitly linked corrective PRs. A later PR that happens to touch the same files is not treated as corrective work. Corrective links use an explicit `Corrective-PR: #<number>` or full GitHub pull-request URL field.

## Account-level allowance observations

Add timestamped observations with their accounting period, reset boundary, and batch identifier:

```sh
bun tooling/model-telemetry/model-telemetry.ts allowance add \
  --value 75 --unit percent --period-start 2026-10-01T00:00:00Z \
  --period-end 2026-11-01T00:00:00Z \
  --reset-boundary 2026-11-01T00:00:00Z --batch observation-batch-1 \
  --contaminated
```

Observations are account-level and always marked `unattributable`; contamination is retained. Overlapping activity means an allowance observation cannot establish exact usage for a session or model. Contaminated observations are excluded from any attributable usage figure. This collector does not estimate individual attribution.

## Outcome and cost semantics

Gate acceptance is the trusted Review Gate `merge-candidate` signal. Actual merge state comes separately from the PR's GitHub state and `mergedAt`. A changed observed model after a needs-fix review is reported as an escalation; subsequent work on the same observed model is a repair attempt. Corrective PRs require an explicit `Corrective-PR` link. Issue reopening is identified when an issue previously observed closed is later observed open.

Saved-session prompt/total/completion token counters are latest-step context/output snapshots; the report never sums them as cumulative spend. Cumulative saved session cost is reported independently and is not presented as account allowance consumption.
